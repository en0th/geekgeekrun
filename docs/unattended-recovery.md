# 0.23.8：找岗位任务自动恢复

找岗位任务原来会把网络断开、列表加载卡住、详情加载超时或短暂的未知读取响应直接记为需要手动恢复。现在这些故障保持在同一次任务中，等待后自动重新连接。

连续失败依次等待5、15、30、60、120秒，之后保持每次120秒；网络故障不设重试次数上限。有新的查看、收集或成功打招呼进度后，下一次故障从5秒开始。任务详情显示“自动恢复中”、原因及下次重试倒计时。用户仍可暂停或结束。

每次自动恢复会关闭原浏览器，取消原浏览器任务中的等待（包括定时休息），等待旧的执行过程退出，再从保存的职位来源和筛选组合继续。任务编号、已完成统计、账号、屏蔽记录、来源计数、请求用量和每日已用人数保留；不新建任务，不放宽筛选条件，不退还已用请求。重试等待不计入模式的累计运行时间。

页面筛选未得到确认时，会重新打开页面并最多尝试三次应用原条件；仍未确认则提示处理，避免错误条件下发送。验证码等待用户在原验证窗口处理，验证后按原流程继续。明确失效的登录、账号切换、平台限制、每日自动目标、模式保护及数据读写错误保留对应处理流程。浏览器文件缺失、证书问题或无效页面地址仍提示检查。

发送按钮已点击而结果无法确认时，不属于可直接重试的读取失败。软件保留待核对记录，不自动重复发送。

安装后可到任务列表继续之前因网络或页面问题暂停的任务；之后同类故障会自动恢复。找岗位配置和系统设置不增加新的选择项。GUI安装版和命令行运行使用同一重试策略。

验证使用故障注入和独立运行目录：

- 对实际GUI和CLI任务循环注入连接失败、详情超时，检查同一次任务自动继续且不退出。
- 模拟连续12次断网，检查延迟上限、进度恢复后重置和手动停止取消。
- 核对发送状态在清理期间变化时，不能进入下一次自动执行。
- 检查旧浏览器的长时间休息可取消，旧工作退出后才恢复状态。
- 检查来源位置、屏蔽名单、账号和已花费的请求用量保留，保护上限和数据错误不被清零绕过。

真实网络和BOSS页面仍可能变化；离线测试不能替代使用者安装后的真实挂机验证。本次未使用真实账号投递。
