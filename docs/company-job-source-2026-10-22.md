# 公司职位来源：身份与页面契约核验

日期：2026-10-22。基线为 `095be28`（PR #12 已合并）。本轮优先验证公司主页/品牌 ID 的职位来源，同时保留既有筛选、预算、恢复和只收集边界。

## 第一批：品牌身份与来源隔离

- 品牌身份使用岗位列表及详情中的 `encryptBrandId`。可接受明确品牌 ID、`https://www.zhipin.com/gongsi/<ID>.html` 或其 `/gongsi/job/<ID>.html` 招聘页链接，统一为同一身份和指纹；跟踪参数不进入身份。
- 只接受 BOSS 的固定主机和品牌路径，拒绝外部主机、嵌入账号、非默认端口、编码路径逃逸和 `/companys/`、`/gongsis/` 等不同实体入口。原始数字公司编号不能替代加密品牌 ID。
- 公司岗位确认同时要求列表品牌、详情品牌及岗位 ID 一致；缺少任何一项均拒绝。公司名相似不授权入库或开聊。
- 普通搜索响应及页面状态不接受隐藏公司约束；从带公司约束的页面切回普通搜索时，导航至清理后的范围，而不是只替换关键词。
- 网络列表缓存把品牌/公司字段纳入来源代次，不能把某公司的第一页和另一公司的后续页拼为同一列表。

新增六项回归覆盖规范化、URL 边界、品牌/岗位核对、普通搜索隔离、切源清理及跨公司分页隔离。该批是来源基础与保护措施，尚未增加可执行的公司采集入口。

第一批 [PR #13](https://github.com/en0th/geekgeekrun/pull/13) 已合并；[PR CI](https://github.com/en0th/geekgeekrun/actions/runs/39734562843)、合并后 [master CI](https://github.com/en0th/geekgeekrun/actions/runs/39735126588) 及发布前验证均成功。

## 第二批：公司招聘页接入

“职位筛选与来源”新增“公司品牌岗位”，可填写公司主页/招聘页链接或品牌 ID，附加展示备注和公司内搜索词；可启用多行并排序。每个品牌与搜索词组合独立轮换、去重，并进入排队快照、模板、恢复指纹及同范围观察比较；修改品牌或搜索词不能沿用旧范围。备注不参与身份判断。

- 使用官网 `/gongsi/job/[c城市编码/]<品牌ID>.html` 页面及其原生 `searchAction()`、`onCurrentPageChange()`，确认 `/wapi/zpgeek/brand/job/querylist.json` 的实际响应。不把普通搜索附加 `brandId` 当作公司来源。
- 原生请求的 `brandId/query/city/positionLv1/salary/experience/degree`、当前页模型、列表岗位 ID/品牌、已登录状态必须一致。列表每页替换，不与上一页拼成无限滚动列表；兼容城市导航后根元素由 Nuxt 包装的情况。
- 城市、薪资、经验和学历使用公司页原生筛选，配置编码须存在，选项也须在当前公司页提供。页面缺失的选项会暂停并提示重新选择，例如公司页不提供普通列表的经验编码 `101` 时，不把它自动改成“不限”。
- 行业和公司规模是品牌固定资料，按当前同岗位详情的编码核对；不符合则跳过该组合，缺少资料或身份无法确认则暂停。保存每条详情和发送前再次核对品牌、岗位与所选城市/行业/规模。
- 继续共用既有本地公司/薪资/城市/经验/岗位内容、硬条件、冷却、限额及只收集逻辑。“收集全部”仍跳过本地求职条件；页面来源和页面筛选始终成立。只收集不沟通，也不在 BOSS 或本地标记不合适。
- 含公司来源的任务关闭全页面详情预载入库，只通过已核验的详情钩子保存；匹配收集须到过滤后的接受钩子才入库，避免启动推荐和相似岗位混入观察集合。纯普通来源任务保留既有预载行为。
- 公司 HTML 导航、原生筛选请求和每页 API 都计入原有累计请求预算；详情计入详情预算。网页服务端渲染内部的服务器请求不可见，不把预算宣传为网站后台请求总量。31/37、401/403/429、异常/非 JSON、分页停滞与品牌变化继续停止，不清空凭证或恢复计数。
- 修复最后一页还有多个岗位时循环提前退出的问题；真实空组合直接进入下一个组合。切回普通搜索清除公司约束；沟通页面返回时等待实际来源路径。

配置结构示例（此处品牌 ID 仅作格式示例）：

```json
{
  "type": "company",
  "enabled": true,
  "children": [{ "enabled": true, "brandId": "0123456789abcdef1nRz", "keyword": "Java", "label": "展示备注" }]
}
```

## 实际网页核验与验收范围

只读使用本机现有会话，在临时浏览器中观察官网自身的链接、请求和页面模型；原 cookie/localStorage 文件和用户数据库保持只读，未发送消息或做不合适标记。公司信息仅从已保存的品牌记录及官网公开链接选取，未用名称猜测品牌身份。

- 公司主页提供独立的 `/gongsi/job/<ID>.html` 招聘页链接，其页面与当前 `.page-jobs-main` 搜索工作台不同，不能直接复用后者的 DOM 选择器。
- 当前工作台的前端表单与请求构造未保留直接附加的 `brandId`。URL 上出现参数不等于公司范围已经生效；该方式未通过核验，不接入任务。
- 初次核验公司链接时，站点多次转入安全验证，之后回到首页；用户手工验证并重新打开窗口后，已确认真实“朴朴超市”公司主页，页面品牌字段与主页 ID 一致，主页有 10 个岗位卡片，并提供独立招聘页链接。
- 安全验证后仍是游客会话，用户另行登录；认证后第一页、第二页原生接口均为 HTTP 200 / code 0，各 15 条，第二页 15 个新岗位 ID，所有岗位品牌均为 `fad1f22e53cb24931HB63d-4`。任务读取官网 Vuex 登录状态，游客结果不能作为完整分页确认。
- 使用生产来源/筛选/响应守卫与分页函数核验：深圳城市筛选返回 15 条，公司内搜索“配送”返回 15 条；城市/5–10K/1–3年/本科组合得到真实匹配的空结果，不以旧列表代替。行业 `100020`、规模 `306` 与同岗位详情一致；不符的规模 `301` 被跳过。
- 在独立临时 SQLite 库使用生产存储插件，只保存经品牌/岗位和过滤核对的 2 条详情、2 条观察。沟通记录 0、标记记录 0、站点沟通/标记请求 0；收集模式的最终发送守卫拒绝开聊。账号信息、cookie/localStorage、完整职位响应和临时数据库不提交到仓库。

验收只针对指定品牌的有界观察，不宣称抓取了其全部在招职位，也不把本地观察差集当作全市场新增。真实站点仅验证读取和隔离收集；开聊/标记后的返回分支使用模拟页面回归，未向真实招聘者发送消息。当前不增加独立 Python 引擎、职位大类选择器或新的浏览器身份持久化方案。

回归覆盖公司配置/模板/快照、原生筛选与不支持选项、Nuxt 包装、分页替换与最后一页、真实空结果、游客/跨品牌/迟到响应/限制停止、请求预算、显式存储和普通来源隔离。各批均运行主进程/渲染器类型检查、完整回归和生产构建；线上 Quality gate 及 Electron 原生 SQLite 按 PR 最终提交验证。
