## 第一批：浏览器与连接诊断

已有的岗位 JSON 响应守卫不能覆盖浏览器尚未启动、Page 崩溃、连接断开、请求没有响应及错误 HTML 文档。通用异常可能每几秒重开浏览器，并把具体原因压成“等待重新检查任务”。本批补齐独立的浏览器健康监听：

- 启动失败区分找不到可执行文件与启动/连接失败；后台窗口状态仍使用原有 99，保持现有行为。
- 监听本任务 Browser 的断连、Page 的关闭/崩溃、BOSS 主文档及岗位接口的网络失败。网络、代理、证书和网站 HTTP 错误提供不同的操作提示。
- 403/429 主文档继续视为受限；安全验证页仍留给用户处理。普通脚本错误、子 frame、静态资源、其他主机及切源引起的 `ERR_ABORTED` 不作为浏览器故障。
- 初始空白/浏览器错误页无法进入任务时明确停止；不会把它当成已认证岗位页。
- 故障会中断正在等待的动作，后续检查点拒绝继续。GUI 保存恢复位置、筛选快照和预算，GUI/CLI 均以 101 停止，等待明确恢复，不自动重启；凭证不因浏览器故障失效。
- 实际点击沟通前登记“结果待确认”，保存确认后的沟通记录后解除。若期间浏览器/连接丢失，则以 87 单独停止，提示先在 BOSS 核对；不提供普通一键恢复，不把未知结果报为发送成功。这里只登记状态，没有新增发送动作。
- 请求预算监听对接同一个健康守卫，CDP 会话先断开、Page 关闭事件后到达时也保留连接故障或发送未知结果的诊断，不让普通预算监听错误掩盖原因。
- 关闭自己创建的浏览器前解除监听，取消中的任务不产生误报；只处理本任务 Browser/Page，未连接或终止用户其它浏览器。
- 诊断只保存固定阶段、原因、已知 `ERR_*` 和 HTTP 状态，不保留原始启动错误、磁盘路径、请求 URL、凭证、代理地址或调试 WebSocket 地址。

本批未修改岗位条件、来源选择、收集策略、沟通授权或配置文件。只收集仍在登记/点击沟通之前被最终守卫阻止；发生浏览器故障后不产生新的发送或标记。

## 第二批：Windows 宿主、协作退出及浏览器联动

Node.js 的 Windows `kill('SIGTERM')` 会强制终止子进程，不执行 POSIX 信号处理器，不能据此保证保存恢复状态并关闭浏览器。[Node.js 文档](https://nodejs.org/api/child_process.html#subprocesskillsignal)

- daemon 为自己启动的 Node/Electron worker 建立私有 IPC，先发送协作式停止消息；worker 使用原有保存→关闭→再次保存→退出流程。重复停止保持幂等，队列仍等旧进程退出后才交接。
- 原有停止超时及仅针对所属进程树的强制清理保留。IPC 不可用时 POSIX 可以回退信号；Windows 等待已有的超时清理，避免立刻强杀而跳过保存。父进程异常断开也触发现有清理入口。
- 真实 Node daemon 回归继续覆盖延迟退出、停止中排队、GUI 断开、恢复、陈旧 worker 消息和不响应停止的浏览器子进程。没有为 Windows 跳过这些用例。
- 真实浏览器与预算监听联动验收发现 CDP 会话断开可能先于 Page 关闭事件，补上统一诊断入口。此时没有继续释放动作，也不会将未知发送结果降为普通可恢复暂停。
- 新增 `Windows host validation`：Windows 2025 上运行两端类型检查、完整 Node 回归、生产构建、真实 Chrome 离线窗口/详情检查/只收集、Electron 原生 SQLite，以及完整 Electron 主进程的 IPC 退出测试。既有 Linux 与 macOS 检查保留。
- `checks / Quality gate` 同时要求三组成功，Windows 失败、取消或跳过均不能通过。PR、master、合并队列和发布前验证继续调用同一 reusable workflow，报告按平台隔离。
- 实际 Windows 检查已完成 469 项 Node 回归、31 项 Electron 原生回归、Chrome 155 离线窗口收集和完整 Electron 39 主进程退出。核验时发现上传动作默认忽略隐藏的 `.ci-reports` 目录，已改为允许隐藏文件、仅上传四类明确报告，并在报告缺失时失败；避免“步骤成功但没有验收附件”。

浏览器验收使用临时 profile、内存 SQLite 和两张离线岗位卡片：一条符合实习/学历/品牌/城市/行业/规模条件，另一条被拒绝；只保存一条观察，发送和标记记录均为 0。验证最小化下换卡与岗位 ID 确认、显示同一验证窗口、页面关闭暂停以及结果待确认停止。BOSS 域名被阻断并断言请求数为 0，未读取真实 cookie/localStorage。

完整 Electron 测试单独移除 `ELECTRON_RUN_AS_NODE`，验证实际主进程可接收停止消息，并在正常退出前完成两次检查点与关闭；不以 Node 模式的 native ABI 通过替代该证据。macOS 本地已通过两套脚本，Windows 的实际版本、结果与报告由最终线上检查记录。

Windows 宿主验证将使用隔离 profile、离线页面和临时数据库，不读取真实 cookie/localStorage，也不访问真实招聘者。宿主 CI 能验证窗口/CDP、存储和执行链路；它不能代替 Windows 上登录 BOSS 后的现场加载、风控或账号验证。
