## 第一批：同范围观察差集

新增 `job_run_scope` 表，只在工作进程取得已确认账号后绑定任务编号和 `v1:SHA256` 搜索范围签名。签名来自排队/恢复使用的冻结配置，覆盖来源、query、排序去重后的职位码、城市、本地条件、公共条件和公司名单；不记录凭证，不把消息跟进设置纳入签名。

- 支持来源全部为明确搜索或公司品牌的任务，公司来源同时绑定品牌 ID 与公司内搜索词。平台推荐/求职期望还依赖账号在线配置，本地配置不足以证明其完整范围，故不自动建立可比基准。
- 多选集和对象属性顺序规范化；来源/组合顺序及未知数组保留原顺序。预算、后台窗口和运行节奏变化不改变筛选范围，但采样量可能不同。
- 签名采用保守匹配：未继承的公共条件变化等也可能阻止比较，优先避免范围错配。
- 相同编号恢复仍属同一轮；改变账号或范围后，该轮永久标记不可比，不能切回旧设置来掩盖已经混合的观察。
- 老数据不补造范围。若首次绑定时已有旧观察，明确拒绝把它当作完整可比任务。
- 自动选取较早、同账号/签名且有观察记录的最近任务；无基准时显示原因，新增数为空，不把所有岗位误标为新。查询层也验证显式基准的账号/范围/先后顺序。
- SQL 按稳定 `encryptJobId` 比较观察集合；不加载全库 ID。台账保留删除详情的岗位。列表、分页、导出、列值、统计和摘要共用差集过滤。

只收集任务的“本次数据”新增“较同范围基准新增”和刷新比较。展示基准编号、当前/基准观察数、增加、重复及本轮未观察到的数量。比较针对本地已观察集合，不表示全量市场，不把“未观察到”解释为下架。详情和 JD 仍使用资料库当前内容，没有逐任务 JD 历史快照。

纯普通来源的收集全部模式保留现有页面预载入库行为，任务观察集合可能包含预载，数量可以大于主动查看数；含公司来源时改为只保存已核验详情，防止相关或启动推荐岗位混入。比较口径是相同冻结配置任务的本地观察集合，不是网页搜索结果全集。

新增 10 项用例覆盖签名、账号与范围隔离、恢复、历史/空基准、显式基准校验、删除详情、查询/导出/统计/摘要一致性，以及真实 SQLite 插件登录钩子。完整 Node 回归 418 项通过，0 失败、0 跳过；主进程和渲染器类型检查及生产构建通过。[PR #11](https://github.com/en0th/geekgeekrun/pull/11) 已在 [PR CI](https://github.com/en0th/geekgeekrun/actions/runs/39726749871) 通过后合并，合并后 [master CI](https://github.com/en0th/geekgeekrun/actions/runs/39727048139) 和发布前验证均成功。

## 第二批：scraper 离线导入

在“资料库 → 职位 → 导入”选择 `boss-zhipin-scraper` 格式，再选文件。先展示字段、前五行和缺失/冲突告警，确认后才写入；不启动浏览器、发消息或做站点标记。使用本地 scraper `b8076fceb9cb5e5e1ae28c155e8c1b894cfec7cc` 的真实导出字段定义，兼容列表 JSON 的 `jobs` 容器、详情 JSON 数组和两种 CSV。

| scraper 字段 | 本地处理 |
| --- | --- |
| `encrypt_job_id` | 稳定岗位主键；缺少时仅从校验过的 BOSS `job_link`/`link` 提取；两者冲突则跳过 |
| `job_id`、`is_new` | 不采用 MD5 身份，也不把外库的新增标记当成本库首次发现或任务观察 |
| `boss_name` / `company` | 公司品牌；不填入招聘者姓名 |
| `encrypt_brand_id`、`encrypt_boss_id` | 有值才建立真实 ID 关系；缺失不按名称生成假 ID |
| `title`、`salary`、`location`、`jd` | 职位名、原薪资文本及单位、地址、JD；缺 JD 不合成，不清空库内已有描述 |
| `company_scale`、`company_stage`、`company_industry`、`boss_title` | ID 已知时补齐缺失关系；已有公司/招聘者记录保持通用导入的仅补缺行为 |
| `scraped_at` | 存为“导入源采集时间（原文）”，不替代发布时间/首次入库时间；无时区不推断时区，CSV 没有时间则保留未知 |
| `security_id`、`lid` 等 | 不导入安全或会话参数 |

新增 `job_import_record` 保存最近导入格式、文件名、本库导入时间、源时间原文、公司品牌和源文件是否缺 JD。CSV 通常不含公司 ID，其公司品牌仍能通过来源记录在职位库、收藏夹和岗位视图展示，不制造公司主键。来源字段可从职位库列设置中显示、过滤和导出；原生文件导入不会复制其他数据库的来源台账。

重复导入按岗位 ID 更新，不产生重复岗位；最近导入记录更新，首次发现保持不变。无源时间的新文件不会沿用上次文件的源时间。每一行的关系、岗位、发现台账和导入记录使用同一 savepoint，某行失败则全部回滚，其他有效行仍可导入。大文件继续沿用每 2,000 行分批提交和进度展示。

新增 7 项导入测试覆盖真实 JSON/CSV 解析、BOM/带前导零的 ID/跨行 JD、错误链接和 ID 冲突、字段及品牌映射、来源时间、缺失关系、月薪/日薪、重复导入、真实 SQLite 查询和失败回滚。另补 1 项账号确认时序测试：在进入岗位页面前记录观察基线，本次页面在账号确认前保存的预载仍可比较；上一未确认尝试的观察则保持不可比，避免只收集全部模式被误判为历史混合任务。主进程/渲染器类型检查、生产构建和 426 项完整回归通过，0 失败、0 跳过；线上 CI 与 Electron 原生结果以 PR 的 checks 为准。仅使用临时内存库和合成文件，未读取或修改真实用户数据库。
