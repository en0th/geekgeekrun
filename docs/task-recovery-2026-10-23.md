# 暂停、继续与异常处理改进

日期：2026-10-23。沿用「把复杂留给系统，把下一步交代清楚」的界面原则，分批验证并合并。

## 第一批：先保证「继续运行」确实可以继续

复核发现，发送结果未知虽然禁止外层自动重启，但检查点仍可出现在「已暂停」中，并提供普通继续入口。另一处只依赖任务快照文件检查运行方式；该文件缺失时，不能据此保证只收集任务不会变为打招呼。

本批补齐：

- 真正点击沟通按钮前，同步保存 `messageSendPending: true`；BOSS 确认且开聊记录写入成功后才解除。状态写入失败会中断后续点击；手动暂停、窗口关闭和进程意外结束不会清除未确认状态。
- 退出码和待确认标记进入检查点。新界面与主进程共同判断是否可以继续；旧检查点结合对应运行的历史记录判断，其他任务及复用编号的旧历史不会改变本次判断。
- 主进程在更新任务配置和派发 worker 前核对检查点及原运行方式。即使配置快照文件缺失，也不能将原只收集任务继续为打招呼。
- 待确认任务显示「先核对上次发送结果」，提供「去 BOSS 核对」和「结束本次任务」，保留数据，不提供直接继续按钮。打开的是 BOSS 会话页，不执行打招呼或标记。
- 模式变化、无法确认的旧打招呼检查点和异常元数据会给出提示，保持停止；明确为只收集的旧检查点继续保留恢复能力。
- 已完成的任务不作为可继续任务；运行中的任务和排队任务仍沿用现有执行方式。

### 验证范围

两端类型检查、完整回归及生产构建按每批最终提交执行。回归覆盖真实检查点文件的重新读取、写入失败时不点击、确认存储失败时保留待确认状态、UI 和主进程拒绝不安全的继续、快照文件缺失时的运行方式校验，以及既有公司身份/岗位 ID 的最终发送前检查。

使用真实 renderer 生产构建和本机 Chrome，配合隔离的合成 IPC 状态，检查普通只收集暂停、发送待确认、模式变更、任务详情及重新加载后的入口。界面验收未启动真实任务、未访问 BOSS，没有真实发送或标记，不计作 Windows 实账号现场验收。

原工作区的运行方案和其他并行改动保留，本批在隔离工作树上实现。
