# 面向个人求职者的流程精简复核

日期：2026-10-23。基于 `d2db3bd` 的现有桌面界面，先改进「找岗位」主流程。

判断标准是用户能否快速回答三个问题：我要找什么、开始后会发生什么、遇到问题下一步做什么。系统自行处理默认节奏、数据保存和安全边界；只有影响用户选择的内容进入主流程。

## 本批改动

| 发现的问题 | 改进后的行为 |
| --- | --- |
| 只收集符合条件的岗位，仍要经过「处理方式」；旧标记策略还可能要求填写公司名单 | 两种只收集范围都只需两步。公司标记策略不再阻挡收集；切回打招呼时仍保留原处理策略及其验证 |
| 运行方式的行为说明藏在问号中 | 两张选择卡直接说明「先收集岗位」与「自动打招呼」的行为。收集范围改为明确二选一；真实打招呼的原有确认保留 |
| 一次展示分类、描述、学历、人数、行业、公司等大量条件 | 外层优先展示岗位、城市、薪资、经验。更多筛选和公司偏好按需展开，已选条件始终显示摘要 |
| 未填写或尚未查看的后续步骤提前显示错误或完成图标 | 后续步骤先显示等待；提交验证发现缺项后再提示错误。定位错误会自动展开对应区域 |
| 「运行预算」「encryptBrandId」等技术表达出现在选择路径 | 使用「自动暂停上限」和「粘贴BOSS公司主页链接」，高级配置继续可查、可改 |
| 开始前只有通用说明，实际范围和条件全部折叠 | 职位来源、目标岗位、城市、薪资及打招呼时的不符处理直接可见；其他条件与运行设置可展开核对 |
| 取消切换到打招呼后，单选框原生选中状态与仍保留的只收集配置不一致 | 取消时从已保存的模式重建控件；配置和单选框共同恢复到只收集 |
| 运行上限配置结构异常时，错误分支调用了不存在的渲染函数 | 页面保留可读提示和重置入口；不自动重置用户配置 |

折叠只改变展示，不会清空或放宽已保存的筛选、公司名单、预算、只收集范围或处理策略。仅在只收集模式下跳过不适用的标记策略校验；打招呼模式继续校验。收集全部岗位仍明确说明不应用求职条件。未修改任何发送、标记或任务执行入口。

## 验证

- 在相同模拟已保存条件下，配置页默认可见输入控件从 20 个降至 9 个。该数量包括页面控件，不等同于必填项数量。
- 使用真实生产 renderer 构建进行本机 Chrome 界面验收。IPC 使用合成配置和隔离桩，不读取用户登录态，不启动任务，不访问 BOSS。
- 检查 1280、960、768 像素宽度，主操作可见，没有页面横向溢出；折叠后实习、学历和屏蔽词仍在摘要中可见。
- 检查更多条件展开、收集范围切换、条件保留、开始前核对以及打招呼切换的取消与确认。异常配置和折叠区错误定位有回归覆盖。
- 主进程/渲染器类型检查、487 项完整回归（0 失败、0 跳过）和生产构建通过；线上检查仍使用主分支所要求的 Quality gate。

本批是界面流程验收，不代表完成 Windows BOSS 实账号现场验收。

## 后续优先级

1. **暂停与恢复**：按原因直接给出登录、检查网络或调整上限的下一步入口；保留详细诊断供排查。发送结果待确认时继续禁止普通恢复。
2. **首次准备**：浏览器优先自动发现并核验，账号状态集中展示；手工路径和诊断收进高级设置。
3. **结果查看**：收集完成后直接进入本次岗位，优先显示匹配原因与来源；统计和复杂表格配置按需展开。
4. **消息跟进**：按发送目的组织内容，明确预览和失败行为；服务商 API、重试和上下文条数留在模型高级设置。

这些后续项需分别验证对应执行链路，不在本批中悄悄改变发送方式或运行策略。
